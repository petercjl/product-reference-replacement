# 产品视觉资产与场景替换

两种模式独立成立。A接收产品照片组或完整详情页，制作、沟通调整并定稿资产图；B接收已有资产图及待修改图片，默认单张，明确批量后整组共用同一资产版本。用户可以只做A，也可以直接做B。

应用负责产品理解、选图布局、用户沟通、提示词、状态及验收。本地脚本只执行明确的裁切排版和记录校验；生成由用户已指定的 `sealseek-media` 能力承担。模式B固定 `nano-banana-pro`，每次1张、两张参考、每图最多4轮。安装Skill不授权生图。

## 输入、输出与入口

- A输入：同款商品图片组、详情页长图，或资产图与调整意见；可选款色规格。A无需待修改场景。
- A输出：一张16:9资产图、高清裁片、来源与覆盖清单、历史版本、用户满意后的定稿引用。
- B输入：一张已有产品资产图＋待修改图片/图片组。可直接使用用户提供的外部资产，无需重新制作或强制补齐原始照片。
- B输出：各图实际结果和验收状态、轮次原件、提示词/任务记录、费用与耗时；批量另交付文件对应和成败清单，共享资产只保存一份。

没有材料或材料角色不清时说明：

> 修改图片请提供要修改的图片或图片组，以及一张产品资产图。如果还没有资产图，可以先提供产品图片或完整详情页，我先帮你制作资产图。

只提供商品资料且明确做资产时进入A；资产＋场景齐全时直接进入B；只有资产时邀请提供场景，或按用户意图调整资产。多个款色或图片角色有关键歧义才追问。图片组未说明批量时，列编号询问先处理哪张，可推荐首张，等待用户选定；不把整组自动作为付费范围。

## 执行准备与按需知识

从当前宿主加载 [能力合同](capabilities.json) 和匹配的 [Codex](adapters/codex.json)、[SealSeek](adapters/sealseek.json) 或 [通用适配](adapters/generic.json)。使用宿主广告的看图能力，不能以文件存在或OCR替代实际视觉检查。

运行 `product-reference-replacement doctor --json`。安装或更新诊断先使用包的 `skill source/status/install/update` 和 `update` 入口；从 `skill source --json` 返回source动态加载当前完整Skill。自定义宿主使用自己解析的明确target-directory，更新后同步相同目录。包未安装时由Agent安装完整npm包；本地依赖缺失按 [工具合同](references/tool-contract.md) 修复包依赖并重跑；媒体未安装不妨碍本地模式A，长图缺切片能力则只阻塞相应长图分支。

采用hybrid知识层，**只在当前知识依赖节点按需加载**：[SCHEMA](references/SCHEMA.md)、[index](references/index.md)、近期 [log](references/log.md)，再加载该节点的query和其必读topic；后续节点资料延迟读取。维护来源清单和开发评估不作为启动阅读材料。

## 模式A：产品资料 → 可复用资产图

### A1 逐图理解与分区

在第一次商品视觉分析前，按 [制作/调整资产图路线](references/queries/make-board.md) 读取产品证据与资产布局方法，再逐张实际看图。普通图逐张看；长详情通过 [依赖合同](references/dependencies.md) 动态加载当前 `semantic-image-slicer`，按其完整流程切片、看预览并逐片检查，覆盖全部源图。

确定同一款色/规格，建立“信息→源图/裁切→清晰度→是否上板”的证据表。外形、比例、可见组件关系、材质外观、纹理、标识和使用状态以原始商品证据为准，未见结构不补成事实。资产表达以商品自身为核心，不依赖某张待修改场景。

按信息覆盖决定格数；每格有明确职责，避免重复。整体16:9，允许主图大格加细节小格，标签如实写正视、斜视、结构细节或表面纹理。编写源图坐标与格位计划，调用脚本 `board render`；字段、坐标和命令见 [工具合同](references/tool-contract.md)。缺关键视角先补图，不调用生成模型虚构商品事实。

### A2 展示、调整与用户定稿

在展示和处理反馈节点加载 [资产沟通方法](references/topics/asset-review.md)。实际查看整板和各格，核对原图、比例、标签和缩放后可读性，然后展示给用户。按用户反馈修改明确分区、图源、标签和布局，用新计划及新目录保存版本。资产沟通没有固定四轮上限。

用户明确满意后，将该消息作为approval_evidence，通过 `asset freeze` 写入定稿记录。不能替用户填写满意；Agent技术检查通过仅代表可供审阅。用户提供现成资产用于替换时走B的 `asset import`，不用伪造A的定稿确认。

A可以独立完成并结束。定稿后提醒：

> 产品资产图已定稿，可以用于后续多张图片。是否现在开始修改图片？请提供要修改的一张或一组图片，并说明单张还是批量；默认单张处理。

若场景图已提供，列出现有图片确认是否开始与范围，无需重复索取。资产满意不自动提交场景生成。

## 模式B：已有资产 → 单张或明确批量替换

### B1 资产、范围与任务绑定

进入B时按 [替换与验收路线](references/queries/replace-images.md) 读取资产使用、场景任务及双重验收方法。看已有资产图，检查款色、标签、关键可见面和纹理是否可辨。外部资产只做检查和导入，不能为每张场景重新绘制资产；不足时说明缺口，让用户决定补图或回A调整。

用户提供资产用于替换是其使用依据，调用 `asset import` 保存路径、版本、哈希与覆盖范围。A已定稿则复用freeze记录。明确 `single` 或用户指定的 `batch` 清单，默认single恰好1张。通过 `job create` 建立不可变任务清单，记录真实用户授权依据、每图上限（最多4）和整批最高请求数/预算。

逐图检查场景、目标产品位置、朝向、尺度依据、人物接触、遮挡、构图光线和文字保持项；每图独立提示词。单次只有两张参考：该图原始场景在前、共享资产图在后。16:9固定的是资产图，最终场景沿用原图最接近的受支持比例，默认2K。

### B2 单张生成与看图迭代

通过 [媒体依赖合同](references/dependencies.md) 动态加载当前 `sealseek-media` 的完整Skill；核验认证、实时模型 `nano-banana-pro`、两图参考、参数及单张输出。指定模型不可用时报告缺口，保持用户选择。

使用 `round prepare` 准备单轮请求；它只输出命令参数，不上传或生成。按媒体Skill先执行dry-run，再在授权范围内submit一次，立即将返回任务JSON用 `round attach` 绑定；持续跟踪同一task_id到终态，再attach最新结果。参数数组需由调用工具按数组或安全引用传递，不进行不安全shell插值。

实际查看结果全图和必要局部，分别比较产品身份与场景保持。用 `round review` 记录该结果hash、实际看图、两项判定及可定位证据。脚本不替Agent看图或生成质量结论。

- 两项均PASS：该图立即结束，交付通过结果。
- 有可定位FAIL且仍有轮次和预算：调整本图的完整提示词后准备下一轮；仍用该图最初场景＋同一资产图。结果图只作为验收证据。
- UNCERTAIN/ANCHOR_CONFLICT：先解决证据或资产歧义，不自动重绘资产。
- 每图含首轮最多4轮；用户要求一次时max_rounds=1。技术失败或未知提交结果先恢复同一task_id，不能自动新建付费请求。保留已预留轮次；不确定是否收费时不能清空记录重置预算。

提示词以简洁的替换任务、参考职责、保留关系和光线为主。商品事实由资产图承担；所有可见结构、比例、组件位置、材质、颜色、文字、标识及连接关系遵循参考，不添加、移除、移动或重新设计组件。商品识别笔记与问题分析单独存档，不长篇重述商品细节。

### B3 批量、恢复与交付

明确batch后按清单顺序逐图完成生成/验收循环，不逐张重复索要已有范围内的授权。10张场景共用同一份资产，单次请求仍num=1；每图独立task_id/轮数/停止原因。最高40次是10×4的上限而非实际必做次数，整体预算优先。

`job status` 查询进度。中断时恢复活动项现有任务，已accepted项跳过。单图不可恢复失败记录后可继续其他条件齐全且授权内项目；共享资产改变、认证或预算问题暂停受影响任务。新资产版本须用户确认范围；旧结果和已有轮数保留，已完成项不自动重做。

通过 `job collect` 保留全部实际轮次原件、记录及编号对比；只有双重PASS的图片才标“已验收结果”。整组交付原文件对应、accepted/exhausted/failed/needs-input清单、轮数、费用/耗时；共享资产一份。费用缺失保留unknown，不能计零。没达标说明最接近候选及差距，不能把技术succeeded当业务通过。

## 失败、能力与演进

- 缺输入/角色不明：回入口引导，已有材料保留。
- 长图切片/看图/字体/本地依赖不可用：报告具体CAPABILITY_UNAVAILABLE，修复后返回当前节点。
- 资产事实冲突或关键视角不足：回A证据/调整节点，或向外部资产提供者索取补充。
- 已有文件：新文件/目录或用户明确批准后的恢复备份；脚本只排他写入。
- 外部生成失败/超时：按媒体Skill诊断恢复同一任务，回B2；不以重提收费请求代替恢复。
- 运行不修改自身Skill、适配或媒体包。重复缺口写入开发评估，另行授权维护；干净上下文回归仅在用户要求时执行。
