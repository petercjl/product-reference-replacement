# 产品与场景共同验收

触发：B2，实际结果下载后。输入是原始场景、同一资产、该轮蓝图和结果全图/必要局部；输出是与结果hash绑定的review；回B2迭代或B3交付。脚本校验声明一致性，不替Agent看图。

## 五项检查归入两道门

| 检查 | 对照依据与标准 | 归属 |
| --- | --- | --- |
| product | 资产中的身份、轮廓、比例、组件拓扑、材质纹理、款色与标识。区分整体透视和真实结构变形。 | 商品门 |
| scene | 原场景中的人物身份、姿态、机位、背景、构图与光线，是否有非目标改动。 | 场景门 |
| contact | 蓝图中的支撑、握持、受力、允许的压缩和接触阴影；轻微手指适配须在真实授权内。 | 场景门 |
| occlusion | 原图可见范围与蓝图前后关系；核查手、腕、前臂、面部是否新增露出或改变遮挡。 | 场景门 |
| text | 场景文字、标识及版式保持；商品文字按资产；资产板标签不迁入场景。 | 场景门 |

每项记录PASS/FAIL/UNCERTAIN/ANCHOR_CONFLICT和可定位证据。该项不适用时可PASS，但证据应说明原因，例如无人物接触或原场景无文字；不能填空或假装做过检查。可见证据不足记UNCERTAIN，一个关键身份变化即商品FAIL，人物姿态改变即场景FAIL。商品正确与整体好看都不能抵消场景失败。

两门均PASS、五项均PASS且issues为空才接受。结果成功下载只是技术成功。精确像素保持不是当前双参考编辑的保证。

## 失败与返回

- FAIL且有预算：写明主要失败层和证据。蓝图有误回B1，保存新版本；否则按编译方法修订完整提示词，回B2用原始两图生成1张。
- UNCERTAIN：先核对原始证据或请求缺失资料；该图暂停，避免把不确定当缺陷重画。
- ANCHOR_CONFLICT：商品身份与受保护场景无法共同成立时说明冲突，用户决定补充视角、改变朝向或放宽指定边界。
- 双门PASS立即结束；每图含首轮最多四次，整批预算优先。其他已授权批量项可按现有状态规则继续。

整批固定资产版本和hash。资产改变时暂停受影响任务并确认新范围，已有轮数和通过项保留。技术失败或未知提交按原task_id恢复。无法达标时交付实际候选、状态和差距，不标为通过。
